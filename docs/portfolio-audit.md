## Mobile scrolling

Mouse-wheel measurement compensation in the iPhone-UA library path has a [focused core patch](timeline-wheel-compensation.md). Touch-like or drag-based scrolling can still exhibit unwanted viewport movement and remains under investigation. Passing Chromium geometry tests does not establish physical iPhone/Safari momentum correctness. Retain the [opt-in development recorder](scroll-diagnostics.md) for reproduction; assess timing with it disabled as well.

## Rendering and storage scale

Virtualization bounds mounted rows, not storage work or all memory. Timeline/Thread projections reuse confirmed acquisition references; typing/presence/drafts do not reconstruct the complete confirmed history. Search runs against fictional authority sources instead of downloading all histories to the UI. Unread count is an absolute authority summary, not an inbox enumeration.

Whole authority buckets are still validated/cloned/written in native transactions, including reads. Thread sorting, journal reads and Search scans can consume CPU/storage at 50k scale. Acquired target windows, aliases, acknowledgments, arrivals and resource revisions can grow during a long mounted session. Profile sustained sessions before introducing read-only/indexed storage or eviction: arbitrary caps can break sparse targets, revisions and pending confirmations. No FPS, latency, bundle or memory improvement has been measured.

## Recovery and navigation

- Local drafts/outbox are identity-scoped and reconciled before retry, but the app promises neither background delivery nor durability after denied/evicted browser storage. Debounced draft keystrokes can be lost before their transaction commits.
- Shared authority changes and journal ingestion use recoverable receipts; multiple authority databases are not globally atomic. Demo maintenance can fail partway through; reload/check storage and retry reset before trusting partial state.
- Postmortem/Action Item fields remain page-local. Ordinary links, commands, sign-out and document unloads warn about unsaved work; same-document browser Back/Forward and unrelated programmatic navigation are not fully guarded. Retained conflict copies disappear on leaving.
- Confirmed human messages have no editing/deletion UI. Tombstones support simulated authority changes and deep-link continuity.

## Browser verification limits and timing debt

Native dialogs, focus retention, keyboard/IME guards, reduced motion, forced colors and responsive geometry have automated checks. Desktop/mobile Chromium emulation does not certify physical-device keyboard/IME, assistive technology, Safari momentum, elastic overscroll or trackpad behavior.

Earlier Windows high-concurrency browser and overlapping unit/browser runs had interaction timeouts; supported lower-concurrency runs passed. Their exact cause remains unresolved. CI uses its existing two production browser workers and one configured retry; development uses one worker and no retries. A prior native-link new-tab timeout was not reproduced in repeated isolation. A reproduced initial resize-anchor capture race was corrected by waiting for committed geometry while retaining the 8px anchor/DOM/Latest assertions. A later context-sheet swipe failure passed its unchanged isolated rerun; its cause remains unestablished. Preserve failures and test reports instead of weakening assertions or attributing all timing failures to the host.

Current commands and test suites are in [README](../README.md#testing) and [Technical Architecture](technical-architecture.md#30-testing-strategy). Exact results belong to the corresponding commit's CI run, not permanent test counts in this document.

## Public demo boundary

The browser owns fictional accounts, authority storage, journal, sessions and workers. This is not server-enforced production authentication or a WebSocket service. Use fictional data only. Settings describes browser/system display preferences rather than an account-preference service. There are no attachments, rich text, real integrations, offline background delivery, publish workflow or complete commander command subsystem.

Netlify setup and outstanding hosted checks are in [Deployment](deployment.md). There is no live URL or license file yet. No screenshots are committed; README gives exact capture recommendations. Product policies, original specification, application code, tests, patches and CI remain essential maintenance inputs.
